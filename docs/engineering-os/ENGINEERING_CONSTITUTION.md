# AI.FO Engineering Constitution

Version: 1.0.0

This Constitution governs engineering missions executed through the AI.FO
Engineering Operating System. The adopted
[Founder Operating Manual](../governance/FOUNDER_OPERATING_MANUAL.md) remains
the source of company doctrine. This document defines only the enforceable
engineering contract that implements it.

## Constitutional rules

1. A GitHub Issue and its authenticated history are the authoritative mission
   declaration and event source. Git, CI evidence, and repository policy are
   authoritative for code and policy. Reporting mirrors grant no authority.
2. Every mission pins this semantic version and the SHA-256 hash of the exact
   bytes of this file before it may become Ready.
3. All authority and state transitions are deny-by-default. An absent,
   malformed, stale, conflicting, or unverifiable rule is a denial.
4. Computed risk may raise but never lower declared risk. Tier 2 includes any
   consequential security, privacy, data, methodology, deployment, cloud,
   spend, schema, public-claim, irreversible, or cross-boundary change.
5. Producer and adversary are distinct identities. The founder is the sole
   merge authority in version 1. Approval for one action never implies
   deployment, cutover, cloud mutation, spend, secrets, customer data, or a
   different artifact.
6. Mission scope is bounded by declared paths, capabilities, ownership,
   frozen-artifact constraints, budgets, and exact repository and revision.
7. Evidence is derived from authenticated state and reproducible validation.
   Assertions in prose are not substitutes for tested results or hashes.
8. Valid adversarial findings return work to remediation. Crossed limits,
   unresolvable conflicts, missing authority, or expanded scope stop or park
   the mission while preserving evidence.
9. Every mission declares an honest rollback or recovery class. Incidents
   preserve the originating mission, evidence, recovery action, and recovery
   verification.
10. Amendments require a versioned repository change, updated schemas and
    tests, a new content hash, and founder approval. Historical mission pins
    and audit records are not rewritten.

## Initial activation boundary

Version 1 authorizes design, local implementation, validation, and founder
review. Auto-merge, deployment, production mutation, Airtable live writes, and
EDGAR integration remain disabled by repository policy.
