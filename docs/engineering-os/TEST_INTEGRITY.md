# Test-integrity enforcement

The test-integrity guard compares authenticated, immutable base and head commits. It binds every tracked path to its Git blob bytes, rejects dirty or unrelated revisions, derives mission and risk truth from GitHub, and emits a machine-generated report even when analysis cannot complete.

The reusable workflow executes only the kernel stored with the reviewed reusable-workflow revision. It never executes code from the pull-request head. A default-branch `pull_request_target` caller pins that reusable workflow to an exact Control Plane commit and grants read-only Actions, contents, issue, and pull-request access.

Executable test discovery is parser-backed and fail closed. Python semantics bind function kind, signature and defaults, decorators and parametrization, return metadata, module collection metadata, enclosing-class bases/decorators/collection state, and inherited skip or `__test__` disablement. JavaScript semantics bind nested suite scopes and suite modifiers; static dot, bracket, computed-string, and alias forms are normalized, while dynamic or indirect collection references that cannot be proven equivalent are rejected. Duplicate runtime identities, unsupported declarations, semantic assertion/body changes, newly inherited skips, and ambiguous renames require an authenticated override. Test-runner configuration is protected recursively in every package.

## Manifest-bound Python imports

Every Python test is parsed with a manifest-bound import resolver before its collection semantics are accepted. A first-party module can resolve only to an authenticated `module.py` or `module/__init__.py`; every parent package initializer is included. Both forms at one identity, a missing initializer or module, a stale digest, a symlink, a path escape, or any other contradictory resolution denies the file. The resolver never imports or executes candidate code.

The resolver traverses recursively with a visited set, so cycles terminate deterministically and every resolved file is charged once to the same aggregate resource budget used by scanning and analysis. The closure fingerprint contains canonical paths, edges, external roots, and collection-time semantic projections. Every manifest-resolved first-party module imported by a test receives a full AST semantic fingerprint, including function bodies and static imports nested in them. Pytest support loaded without an explicit import is represented by mandatory implicit edges from each test to every ancestor `conftest.py` and package `__init__.py` present in the authenticated manifest. Literal `pytest_plugins` declarations are resolved recursively through the same manifest; computed, duplicate, or contradictory declarations fail closed. These rules are independent of repository paths, configured test globs, and directory placement, so executed first-party support cannot move outside a configured test root or rely on pytest auto-discovery to evade semantic accounting.

Collection-time setup admits only bounded syntax: literals, audited type metadata, frozen dataclass declarations, proven-safe frozen dataclass instantiation, regular-expression compilation, known unittest skip and pytest parametrization decorators, exact-provenance `pytest.fixture` decorators with closed literal options, and `Path(__file__)` chains using bounded `resolve()`, `parent`, `parents[index]`, and literal path joins. Fixture options are limited to bounded `scope`, `autouse`, `name`, literal `params`, and literal `ids`; callable IDs, computed parameters, unknown options, and shadowed fixture spellings fail closed. Executable helpers and decorators are bound to their audited built-in or external import provenance; redefining or aliasing an untrusted object over a trusted spelling removes that authority. Custom metaclasses, arbitrary decorators, descriptor and class-subscription hooks, computed plugin declarations, and unbounded `__init_subclass__` bodies fail closed. The sole admitted `__init_subclass__` body consists of bounded constant assignments to pytest/unittest collection flags. A frozen dataclass is instantiable during setup only when it has no base class, lifecycle hook, implicit class hook, or `default_factory`; ordinary frozen dataclass declarations remain supported without granting setup-time instantiation.

Static imports inside every first-party function body are also resolved. Dynamic import primitives, runtime import-module dispatch, unresolved imports, arbitrary collection-time calls, namespace mutation, import shadowing, and unsupported computed setup deny the file. Runtime test and imported first-party bodies retain full semantic fingerprints. A direct builtin `getattr(subject, "literal"[, default])` with a non-reflection literal is admitted because it does not itself mutate collection state. The only non-literal form is a direct return from a structurally bounded `__getattr__(self, name)` transparent proxy. Aliasing `getattr`, using any other computed attribute target, targeting a reflection primitive, or using `globals`, `locals`, `vars`, `setattr`, `delattr`, `__setattr__`, `__delattr__`, `eval`, `exec`, `__import__`, `import_module`, or reflective class, code, function, frame, module, or namespace attributes fails closed anywhere in the body. Parser or projector recursion exhaustion is converted to a structured denial by the kernel itself.

The closed external-root set is audited in `engineering_os/python_imports.py`. It currently contains the Python standard-library roots required by the complete Control Plane corpus: `__future__`, `argparse`, `ast`, `collections`, `concurrent`, `copy`, `dataclasses`, `datetime`, `hashlib`, `io`, `json`, `keyword`, `math`, `os`, `pathlib`, `re`, `shutil`, `sqlite3`, `subprocess`, `sys`, `tempfile`, `time`, `typing`, `unittest`, `urllib`, and `zipfile`, plus the collection framework `pytest`. A same-named first-party file or package is shadowing and fails closed. Adding an external root requires code, adversarial tests, review, and immutable-kernel repinning.

Coverage deltas are accepted only when a sealed trusted adapter result binds the coverage bytes and source manifest to an independently retrieved successful GitHub Actions run, exact workflow revision, artifact identity and digest, repository, commit, and transport timestamp. Repositories without coverage evidence do not need an attestation; configured coverage with unavailable or mismatched transport evidence fails closed.

The adapter and kernel share one non-resetting resource budget across policy and manifest validation, Git discovery, filesystem reconciliation, Python import traversal, parsing, semantic comparison, GitHub transport, coverage verification, and report construction. Caps cover filesystem entries (including directories), total processed bytes, paths, Git records, GitHub pagination/items/responses, and coverage artifacts. Directory paths are validated and charged before enqueueing, so wide empty fanout and deep trees cannot evade the streamed traversal budget. Resource failures preserve the pre-initialized machine denial report.

The aggregate processed-byte ceiling is 256 MiB. The live Package 8 base/head workload measured 139,890,135 charged bytes under the shared accounting model; 256 MiB admits that reviewed workload with bounded growth room while the independent file-count, per-file, path, Git-record, GitHub-response, and coverage caps continue to fail closed.

## Activation boundary

The caller does not enforce a PR until the caller commit itself is merged to the default branch and the required status check is configured. That bootstrap interval is an explicit enforcement gap; it cannot be closed by code inside the same unmerged PR. Closing it requires founder-approved merge and, separately, founder-approved live branch-protection configuration.

The first AI.FO-Demo policy introduction is separately fail-closed. Every base-policy consumer normally resolves the policy blob from the immutable base commit. Only when that blob is absent may the resolver use the head policy, and then only when the repository is exactly `josephmccann/AI.FO-Demo`, the base is `52ca01c7c8b034b212feede58ddcc77d9c37c388` or its descendant, the policy path has never changed between that frozen bootstrap base and the current base, and the policy bytes have SHA-256 `27f04a05fece1cfb8e85b7da641f8d3c98592ebc1d7b943be5b99fd0e3b8cf81`. The frozen bootstrap commit must itself have no policy object. A missing or contradictory repository, ancestry, path history, commit, Git object, mode, or digest produces no policy output and terminates validation. After the base contains a policy, the candidate policy can never replace it through this bootstrap path.

That same first activation predates a default-branch Demo command workflow capable of producing a bot-authored `mission.ready` event. Test-integrity therefore accepts one initial-ready attestation only for open Demo PR 202 on branch `codex/eos-package-8`, open mission issue 201, founder-authored GitHub PR and issue evidence, the exact base above, an empty event history, and mission declaration SHA-256 `b91e5315d29c8ba40134efd6d38e366781f30d2070cd18c8739c2ffd3ced8e23`. The mission declaration includes the three exact `lib/api-spec` files required by the reviewed generated-client validation repair; no wildcard scope was added. The attestation hash binds the exact head SHA and all fixed identities. Any event, edit, author/state mismatch, branch change, repository change, or malformed evidence disables the bootstrap and restores the ordinary authenticated `mission.ready` requirement.

Authenticated, atomically consumed override interfaces exist in the kernel. The live workflow deliberately accepts no override, reviewer, or approval inputs. Overrides remain fail closed until the evidence and audit package supplies a trusted durable consumption ledger across workflow runs. Runner-local storage is not accepted as durable replay protection.
